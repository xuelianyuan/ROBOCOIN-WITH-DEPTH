## RIFE 能否用于 Metric 修复

**可以作为短时云斑的候选方案：用 RGB 求流场，用较可靠的 Metric 深度帧填回云斑时刻。效果和绝对深度精度需另行验证。**

RIFE 原论文第 4.4 节、式 (8)、图 9 已演示通过 RGB 图像估计中间流场和融合权重，再插值 MiDaS 深度图；论文明确指出忽略物体 z 轴运动时可得到视觉合理效果。这支持深度插值的技术路径，不构成对本数据集 Metric 云斑修复精度的证明。[RIFE 原论文](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136740608.pdf)

以下是针对当前项目的方案推断，不是已经验证的修复结果：

1. 对疑似坏帧区间 `[s,e]`，寻找前后的可靠深度锚点 `a<s`、`b>e`，同时读取对应 RGB。锚点优先人工复核，不能直接把检测阴性当作深度准确。
2. 对每个原始目标帧 `t`，设 `tau=(t-a)/(b-a)`，RIFE 从 `RGB_a, RGB_b, tau` 估计目标坐标指向两个源帧的流场 `F_ta,F_tb` 及融合权重 `m`。
3. 生成候选深度：`D_candidate = m*warp(D_a,F_ta) + (1-m)*warp(D_b,F_tb)`。只有确认深度本来就在毫米等统一物理单位时，才能按该单位解释结果；gray12le 编码格式本身不能证明数值就是毫米。
4. 细化云斑区域 mask，加上遮挡、有效深度、越界、双侧深度一致性及 RGB 重投影检查，只在通过检查的坏区域替换。其余区域保留原 Metric。当前 320 宽度检测 mask 是候选纹理，不能直接视为精确修复分割。
5. 保持原始帧数、帧率和时间戳。这里是补回坏帧的深度，不是把 30 FPS 视频转成 60 FPS；不通过递归合成帧作为新锚点。

单帧坏点的直观例子：第 7 帧有云斑、6 和 8 帧可靠时，从 6/8 的 RGB 估计 `tau=0.5` 的流，将 6/8 的 Metric 深度投向第 7 帧，检查合格后只替换坏区域。这个例子说明方法，不表示已经确认该视频第 6/8 帧的真实深度正确。

## 哪些情况不适合只用 RIFE

| 情况 | 原因与建议（项目推断） |
|---|---|
| 孤立帧或 2–3 帧短区间，前后有可靠锚点、动作平缓 | 适合优先做小样本对照实验；需保护抓手、物体边缘 |
| 前后锚点也有云斑或共同尺度偏差 | warp 会把错误传播过来；先修锚点或重新估计深度 |
| 抓手快速接近相机、抬升物体、相机平移造成深度明显变化 | 2D 光流只能提供对应关系，不能独立恢复目标时刻的真实 z 深度；需要目标帧深度先验或 3D 运动约束 |
| 遮挡解除、物体只在中间时刻出现 | 双侧锚点缺少该表面信息，无法靠两帧复制恢复可靠深度 |
| 长段云斑、视频开头/结尾缺少双侧锚点 | 不宜强行外推；考虑 RGB 引导的空间修复、深度精化或重新推理 |
| 只有 H.264 灰度预览视频 | 预览值域不等于物理深度，必须回到原始深度数组/视频 |

RIFE 的融合 mask 是图像合成的权重，不能当作经过校准的深度正确概率。即使光流准确，双线性采样、前后深度融合和空间平滑也会改变深度值。保留数值单位不等于保证 Metric 几何准确；z 轴运动限制在原论文第 4.4 节已有说明。[RIFE 原论文](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136740608.pdf)

## 本仓库可复用的内容与差异

以下结论来自本地代码阅读，没有执行 RIFE 推理：

- `src/depth_repair/da3_rife.py:DA3RIFEDepthRepair._interpolate` 已实现 RGB 求流、warp 单通道深度、sigmoid 融合和插值时间轴，可以作为后续复用起点。
- 该类默认流程是均匀采样后重新运行 DA3，再补帧；`run_refine.py --stage rife` 使用映射后的采样深度。两者都没有“自动筛出可靠的原始 Metric 锚点并仅修云斑”的逻辑，不能直接把现有命令等同于这项修复。
- 当前 `_interpolate` 对插值帧执行 `5×5 Gaussian blur`，并整帧合成，没有目标云斑 mask 或深度可靠性拒绝规则。这些都需要在未来实现中评估，不宜默认作用于精细边缘。
- 本地 `train_log/RIFE_HDv3.py` 标记模型版本 4.25。包装层的 `scale_list=[16,8,4,2,1]` 与该版本 `Model.inference` 的 `[32,16,8,4,1]` 不同；后续需核对尺度设置及接口。这里仅记录差异，未判定它造成云斑，也未修改它。
- `_rgb_to_tensor` 与 `_depth_to_warp_tensor` 使用 `.cuda()`，并要求 RGB/深度坐标尺寸一致。后续要验证设备、权重加载、相机与时间同步、流场缩放和有效深度 mask。

Practical-RIFE 官方实现支持指定插值倍率及模型目录，项目说明要求使用对应权重包里的 Python 模型代码。它是图像插帧入口，不能直接代替当前项目的 Metric 修复流程。[Practical-RIFE 官方仓库](https://github.com/hzwer/Practical-RIFE)

## 其他可对照的方法

| 方法 | 依据 | 针对本项目的适用性判断与限制 |
|---|---|---|
| RGB 引导的 guided filter / joint bilateral | 保边缘滤波可用另一幅图作为引导；joint bilateral 方法有深度相关应用。[Guided Image Filtering](https://people.csail.mit.edu/kaiming/eccv10/index.html)、[Joint Bilateral Upsampling](https://graphics.uni-konstanz.de/publikationen/Kopf2007JointBilateralUpsampling/index.html) | 用作轻量空间基线，适合较平滑表面；需防止 RGB 纹理写入深度以及真实薄物体被抹平。对大尺度低频云斑不保证有效 |
| 目标 RGB 到邻帧的光流 + 稳健时间融合 | RAFT 是两幅图间的稠密光流估计模型。[RAFT 官方代码](https://github.com/princeton-vl/RAFT) | 我们已有目标时刻真实 RGB，可直接求目标到邻帧的对应，再对 warp 深度做加权中值/稳健融合；这是修复方案推断，仍需处理遮挡、z 运动与尺度偏差，不声称优于 RIFE |
| RGB-D 深度精化，如 LingBot-Depth | 联合 RGB 和带噪/缺失深度进行补全和精化，官方强调 Metric 尺度。[LingBot-Depth 官方仓库](https://github.com/Robbyant/lingbot-depth) | 适合缺少可靠时间锚点的情况；仓库已有 `LingBotDepthRepair`。输入若是单目预测 Metric 而非真实传感器深度，需验证域差异和尺度，不能照搬传感器数据结论 |
| 视频深度重新估计，如 Metric Video Depth Anything | 使用时空建模改善视频一致性；官方提供 Metric 模型。[CVPR 2025 论文](https://openaccess.thecvf.com/content/CVPR2025/html/Chen_Video_Depth_Anything_Consistent_Depth_Estimation_for_Super-Long_Videos_CVPR_2025_paper.html)、[官方代码](https://github.com/DepthAnything/Video-Depth-Anything) | 可作为长段异常的替代输出对照，计算成本较高；需要单独验证机器人室内场景和绝对尺度，不保证特定云斑消失 |

仅做全局直方图/quantile 分布映射不直接处理空间纹理；当前 `run_refine.py` 也明确说明其可能放大局部起伏，因此不应将分布对齐当作云斑去除方案。

## 后续实验建议，本次不执行

优先比较三种输出：原 Metric、RGB 引导空间滤波、RGB 引导 RIFE 的局部替换。先选两个数据集、不同视角中人工复核的单帧和 2–3 帧事件，再加入快速抓取、遮挡和长段样本。RIFE 与目标 RGB 光流方案可在同一套可靠锚点上对照。

评估同时覆盖坏区和原本正常区：固定显示范围的视觉比较、运动补偿后的时间误差、深度边缘/点云结构、无效像素比例、正常区变化量。存在可靠深度真值时测量 MAE/RMSE/尺度偏差；Nested 或另一个预测模型只是参考，不是真值。

不要只用“检测云斑帧数下降”作成功条件：平滑能降低纹理检测分数，却也可能破坏深度几何。只有视觉、时间一致性和 Metric 精度共同改善，才足以支持批量修复。
